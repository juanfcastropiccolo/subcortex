Anatomía de subcortex

Un LlmAgent de ADK es la corteza: percibe, compara y produce una intención. subcortex es todo lo que en el cerebro decide alrededor de ella. Estas cuatro figuras muestran cómo se conectan las clases, qué pasa en un turno y cómo el experimento A/B mide la diferencia.

ADK (framework) subcortex (la librería) opsworld (simulador) demo / tests

1 · El experimento, de punta a punta

La misma secuencia de incidentes (mismo seed) alimenta dos corridas del mismo agente. La única diferencia es una llamada: subcortex.attach(app).

2 · Un turno del bucle córtico-estriatal

ADK ya tiene el bucle: el modelo propone una function call, la tool responde, el modelo vuelve a mirar. Los cinco plugins se cuelgan de sus hooks. Un veto no rompe el bucle: devuelve un resultado de tool y el modelo re-itera.

3 · Diagrama de clases

Las abstracciones de ADK (arriba a la izquierda) no se tocan: subcortex hereda de BasePlugin, envuelve FunctionTool y se registra en App.plugins. Todo el estado persistente vive en EpisodicStore.

4 · Las abstracciones, una por fila

Qué hace cada pieza, a qué paso del ensayo responde y cuál es su interfaz mínima. Si una fila no tiene análogo cerebral es infraestructura, no mecanismo.

5 · Orden de los hooks

El orden de registro es [Prediction, Gate, Memory, Habit, Interoception]. Importa porque ADK corta en el primer valor no-None y porque cada plugin de after_tool lee lo que escribió el anterior.

before_model

  1. Prediction inyecta el protocolo
  2. Gate no interviene
  3. Memory inyecta precedentes y reglas
  4. Habit puede devolver la function call y cortar
  5. Interoception inyecta el estado interno
El bypass de hábito nunca aplica a acciones irreversibles.

after_model

  1. Gate cuenta llamadas reales y tokens
  2. Gate reduce varias acciones paralelas a la de mayor valor
No corre cuando la respuesta la produjo un hábito: por eso llm_calls mide solo llamadas reales.

before_tool

  1. Prediction valida y guarda la predicción pendiente
  2. Gate decide: None (ejecuta) o {status: vetoed}
Un dict devuelto saltea la tool, pero after_tool corre igual con ese dict: todos los plugins ignoran vetoed y rejected.

after_tool

  1. Prediction calcula el error y lo publica
  2. Memory actualiza dopamina y escribe si hubo sorpresa
  3. Habit compila o des-habitúa
  4. Interoception actualiza contadores y tone
Un error de tool se convierte en {status: error, observed_effect: worsens} para que el bucle siga y se aprenda de él.
